# План: ai_Pobisk

Супервизор, который выполняет задачи из `configs/tasks/`, используя `.agents/skills/`.
Модели иногда останавливаются — ai_Pobisk определяет, фатально ли это, и продолжает если нет.
Модели иногда спрашивают — ai_Pobisk решает, в его ли компетенции вопрос, и отвечает.

Стартовая способность: ai_Pobisk настраивает себе модель-мета-уровень и работает через неё.
Далее — рост до уровня современных harness.

---

## Принципы (не нарушать)

1. **Ноль внешних зависимостей.** Только python3 stdlib + bash. Репозиторий
   клонируется и сразу работает — как сейчас.
2. **Оркестрация в bash, логика в python.** Bash — процесс/env/exec/TUI.
   Всё остальное — импортируемые python-модули. Не плодить heredoc'и.
3. **Не переписывать скиллы.** 2800 LOC с накопленными знаниями о граблях
   провайдеров (404-каталог NVIDIA, 402 `th-orchestra`, таймауты glm/kimi).
   ai_Pobisk — слой *над* ними.
4. **Никаких бесконечных циклов.** Любой retry — с явным лимитом.
5. **ai_Pobisk не делает задачу сам.** Он нанимает рабочую модель и следит за ней.

## Этапы

### 1. Единый словарь исхода — `_shared/outcome.py`

**Цель:** любой скилл возвращает машиночитаемый исход вместо своего диалекта.

```json
{"outcome": "ok|retry|rotate_model|rotate_account|fatal|question|loop_guard",
 "skill": "cline", "model": "...", "account": "...",
 "detail": "сырой текст ошибки", "http": 429, "elapsed_ms": 1200}
```

Семь исходов, и это вся лексика мета-уровня:

| Исход | Что значит | Действие ai_Pobisk |
|---|---|---|
| `ok` | задача сделана | следующий шаг |
| `retry` | transient: 5xx, timeout, 429 | повторить, лимит N |
| `rotate_model` | лимит именно этой модели | другая модель, тот же аккаунт |
| `rotate_account` | лимиты/ключ аккаунта | другой аккаунт |
| `fatal` | не продолжить никогда (нет ключа, сломан конфиг) | остановить, сообщить хозяину |
| `question` | модель задала вопрос | этап 5 |
| `loop_guard` | крутится | остановить |

**Шаг 1а.** Адаптер к каждому скиллу: обёртка, которая вызывает существующий
скрипт и переводит его exit code + stderr в `outcome`. Скиллы **не меняем**.

**Шаг 1б.** Классификатор текстов: `src/classify.py` с паттернами, собранными из
того, что уже разбросано по скиллам (cline's `is_model_limit`, opencode's
`DEAD_PATTERNS`/`AUTH_PATTERNS`/`RETRYABLE_RE`, freebuff's 403/HTTP, nvidia's
404/503/timeout). Одно место вместо пяти копий.

Правила, уже известные и обязательные к переносу:
- `429/503/529/timeout` → `retry` (НЕ fatal — NVIDIA 503 регулярный)
- `401/403/bad key` → `rotate_account` (ретраем не починится)
- `402 $0` / `credit insufficient` → `rotate_account` (не модель!)
- `404 Model not available` → `rotate_model` (только эта модель)
- `Daily free model limit reached` → `rotate_model`

**Критерий:** каждый из 5 скиллов выдаёт `outcome` на искусственном прогоне.

### 2. Модель мета-уровня — `configs/ai_pobisk.yaml`

ai_Pobisk настраивает себе модель для рассуждений. Отдельно от рабочих: рабочая
модель пишет код, мета-модель решает «что делать дальше». Мета должна быть
**быстрой и дешёвой** — она вызывается на каждой остановке.

```yaml
meta:
  # приоритет: кто первый живой, тот и мета-модель
  candidates:
    - {skill: nvidia,      model: "z-ai/glm-5.3-flash"}    # S+, уже healthy
    - {skill: tokenharbor, model: "qwen3.8-flash:free"}    # AA #19, дёшево
    - {skill: nvidia,      model: "nvidia/nemotron-3-nano-omni-30b-a3b-reasoning"}
  max_tokens: 512          # мета отвечает коротко
  timeout_sec: 90
  require_json: true       # ответ строго JSON, иначе переспрос

budget:
  max_retries_per_step: 3
  max_model_rotations: 10     # все модели одного аккаунта
  max_account_rotations: 5
  max_meta_calls_per_task: 40
  max_wall_clock_sec: 3600

fallback:
  # мета-модель недоступна -> детерминированные правила, без LLM
  on_meta_unavailable: rules_only
```

**`on_meta_unavailable` критичен:** если мета-модель умерла, ai_Pobisk не
замирает, а работает на таблице правил из этапа 1. Деградация, не отказ.

**Критерий:** `ai_Pobisk --self-test` находит живую мета-модель и печатает её.

### 3. Каркас `ai_Pobisk` + диспетчер задач

```
ai_Pobisk                     # bash: env, secrets, exec python
src/
├── main.py                   # CLI: run / list / status / self-test
├── dispatcher.py             # читает configs/tasks/*.md
├── supervisor.py             # цикл: step -> outcome -> решение
├── meta.py                   # вызов мета-модели (+ rules-only fallback)
├── classify.py               # этап 1
├── adapters/                 # по одному на скилл
│   ├── cline.py opencode.py freebuff.py nvidia.py tokenharbor.py
└── journal.py                # лог: что делал и почему
```

Задача = markdown из `configs/tasks/`. Первая:

> Прочитать `_Games/igrasu.ru/AGENTS.md`. Добавлять новые игры.

Диспетчер: читает файл, строит план шагов, отдаёт супервизору. Порядок — по
имени (`01`, `02`, …). Пустой файл (`02.безопасность.md`, 0 байт) — пропуск с
замечанием, не падение.

```bash
./ai_Pobisk.sh                    # все задачи из configs/tasks/
./ai_Pobisk.sh --task "01 добавка.md"
./ai_Pobisk.sh --list             # что нашёл и статус
./ai_Pobisk.sh --self-test        # мета-модель + все адаптеры
./ai_Pobisk.sh --dry-run          # план без запуска моделей
```

**Критерий:** `--list` показывает 01 и отмечает 02 как пустой. `--dry-run` на 01
печатает план.

### 4. Остановки: фатально или нет

Цикл супервизора:

```
step -> adapter -> outcome
  ok             -> следующий шаг
  retry          -> повторить (max_retries_per_step)
  rotate_model   -> другая модель
  rotate_account -> другой аккаунт
  question       -> этап 5
  fatal          -> стоп, доложить хозяину
  loop_guard     -> стоп, доложить
```

Мета-модель подключается **только когда таблица правил не дала ответа**, либо:

- исход `fatal` — спросить: точно ли фатально? Может, есть обход
- счётчик retry исчерпан — спросить: что делать
- неопознанная ошибка — классифицировать

Промпт к мете (строго JSON, коротко):

```
Рабочая модель остановилась. Контекст: skill, model, outcome, detail,
что уже пробовали, бюджет остаток.
Ответь JSON: {"verdict":"fatal|retry|rotate_model|rotate_account|question",
"confidence":0..1,"reason":"одна строка","action":"..."}
```

JSON не распарсился → переспросить один раз, потом `rules_only`.

**Критерий:** искусственный `fatal` (отозванный ключ) → стоп с внятной причиной.
Искусственный `429` → продолжение без участия хозяина.

### 5. Вопросы от модели: в моей ли компетенции

Модель спрашивает («какую БД использовать?»). ai_Pobisk решает:

- **В компетенции** — есть в `AGENTS.md`/`configs/`/контексте задачи → ответить сам
- **Не в компетенции** — спросить хозяина, сохранить вопрос, ждать
- **Неоднозначно** — спросить мету

Источники компетенции: `AGENTS.md`, `README.md`, `configs/*`, `SKILL.md` задачи.

```yaml
questions:
  auto_answer_from: [AGENTS.md, README.md, configs/, docs/]
  ask_owner_when: "confidence < 0.6"
  max_pending: 3           # больше стоящих вопросов -> стоп, не спамим
  timeout_sec: 600         # ждать ответа хозяина
```

Ответы логируются в journal — чтобы не переспрашивать одно и то же дважды.

**Критерий:** вопрос, ответ на который есть в AGENTS.md, закрывается без хозяина.
Вопрос вне компетенции уходит хозяину.

### 6. Журнал и состояние

`.ai_pobisk/state.json` + `.ai_pobisk/journal.md`:

- какая задача, какой шаг, какая модель/аккаунт
- все остановки и вердикты (fatal/retry/…)
- все вопросы и ответы
- потрачено: вызовы, время, ротации

Зачем: возобновление после прерывания, разбор «почему он так сделал», и защита
от повторения одного провала.

**Критерий:** убить процесс на середине → перезапуск продолжает с того же шага.

### 7. Тесты

```
test/
├── test_classify.py      таблица ошибок -> outcome (быстро, без сети)
├── test_dispatcher.py    парсинг configs/tasks, пустые файлы
```

`unittest` из stdlib, без pytest. Первые тесты — на `classify.py` и `meta.py`:
там чистая логика, считается за секунды, ловит больше всего багов.

**Критерий:** `python3 -m unittest discover test/` зелёный.

### 9. До уровня современных harness

После 1-7, по мере надобности:

- **Контекст:** компрессия истории, чтобы длинная задача не упиралась в лимит
- **Инструменты:** дать рабочей модели read/grep/glob/edit/run через протокол
- **Параллельные суб-агенты:** несколько моделей на независимых подзадачах
  (база уже есть — `parallel` в NVIDIA)
- **Планирование:** мета строит план и перепланирует при провале шага
- **Песочница:** изоляция запуска, чтобы плохая команда не убила систему
- **Обратная связь от результата:** прогон тестов/линтера как критерий шага

## Риски

| Риск | Митигация |
|---|---|
| Мета-модель тоже падает | `on_meta_unavailable: rules_only` — деградация, не отказ |
| Мета отвечает не JSON | переспрос один раз, потом правила |
| Бесконечный цикл retry | жёсткие лимиты в budget + `loop_guard` |
| Мета дорогая/медленная | отдельная быстрая модель, `max_meta_calls_per_task` |
| Скилл меняет свой exit code | адаптер — единственное место, где это чинится |
| ai_Pobisk сам ломает репо | песочница и `dry-run` до реального запуска |
