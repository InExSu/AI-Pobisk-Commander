# План: мониторинг ai_Pobisk.sh

## Что есть сейчас

| Есть | Чего нет |
|---|---|
| `journal.md` — события в текстах | машиночитаемых метрик |
| `state.json` — статус задач, шаг, счётчики | времени шага, стоимости, токенов |
| `Outcome.elapsed_ms` на каждый вызов | агрегатов (RPM, p95, доля ошибок) |
| `model-stats.json` — p95/jitter/uptime | живой картины «что происходит сейчас» |
| команда `status` (посмертно) | наблюдения во время прогона |
| ротация логов по размеру (`logrot.py`) | — |

Главная дыра: **не видно, работает ли прогон прямо сейчас, и где он застрял.**
События пишутся, но их некому агрегировать.

---

## Принципы

1. **Метрики не ломают прогон.** Любая ошибка в мониторинге — `except: pass`.
2. **Структурные события.** `journal.md` для человека, `events.jsonl` для машины:
   одна строка = одно событие, поля фиксированы.
3. **Ноль зависимостей.** Только stdlib. Ни Prometheus, ни Grafana не требуется:
   Prometheus-совместимый текст отдаётся обычным `http.server`.
4. **Наблюдение — отдельный процесс.** Монитор не должен замедлять супервизор.

---

## Этап 1. `events.jsonl` — машиночитаемые события

**Цель:** каждое событие — одна JSON-строка. Агрегировать можно任何时候,
включая постфактум по уже собранным прогонам.

Файл `.ai_pobisk/events.jsonl`, append-only, ротируется `logrot.py`.

Типы событий:

```json
{"ts":1789900000, "run":"2026-09-20T21:00", "task":"01 безопасность.md",
 "step":1, "type":"step_start", "skill":"cline", "model":"..."}

{"ts":..., "type":"attempt", "skill":"cline", "model":"...",
 "outcome":"retry", "detail":"transient HTTP 429", "http":429,
 "elapsed_ms":1200, "attempt_no":2}

{"ts":..., "type":"outcome", "outcome":"ok", "elapsed_ms":98000}
{"ts":..., "type":"nudge",   "attempt_no":1}
{"ts":..., "type":"question","detail":"...", "answered_by":"local|meta|owner"}
{"ts":..., "type":"rotate",  "from_model":"...", "to_model":"..."}
{"ts":..., "type":"task_end","result":"done|failed|fatal|exhausted",
 "wall_ms":600000, "attempts":{"retry":2,"model":1}}
```

Реализация: `src/metrics.py` с одним вызовом `emit(type, **fields)`,
подключается в `journal.event()` — журнал и метрики пишутся из одной точки.

**Критерий:** после прогона `wc -l events.jsonl` > 0 и строки парсятся.

## Этап 2. `ai_Pobisk.sh status --live` — агрегаты по прогону

Читает `events.jsonl` и печатает сводку:

```
run 2026-09-20T21:00  4 tasks  3 done  1 failed
wall 42m  attempts 17  retries 5  nudges 2  rotations 3
outcomes: ok 4 · retry 5 · rotate_model 3 · fatal 1
p50/p95 step: 180s / 610s
slowest: 03 добавка.md (21m)
skills: cline 12 calls, nvidia 5 calls
```

Подкоманды:
- `status` — как сейчас (по state.json)
- `status --live` — агрегаты по events.jsonl текущего прогона
- `status --json` — для скриптов

**Критерий:** `status --live` после прогона показывает те же числа, что summary.

## Этап 3. Живой монитор во время прогона

Долгий прогон (часы) сегодня выглядит как молчащий терминал.

```
./ai_Pobisk.sh watch          # раз в 5с: что делают задачи
./ai_Pobisk.sh watch --json
```

```
21:04:12  01 безопасность  cline  glm-5.3-flash   step 1   running 6m12s
21:04:12  02 Тесты         cline  solar-pro4      step 1   retry 2/3  12s
21:04:12  03 добавка       —      —               queued
```

Читает `events.jsonl` + `state.json`, не трогает сам прогон.
Отдельно: `./ai_Pobisk.sh tail` — последние события (аналог `tail -f`).

**Критерий:** во время прогона `watch` показывает текущую задачу и модель.

## Этап 4. Prometheus-совместимый экспорт

Для внешних систем (Grafana, алерты) — без зависимостей:

```
./ai_Pobisk.sh serve --port 9099
```

`GET /metrics` отдаёт текст в формате Prometheus:

```
# HELP aipobisk_task_last_status Status of each task (1=done,0=other)
aipobisk_task_last_status{task="01 безопасность.md"} 1
aipobisk_attempts_total{skill="cline",outcome="retry"} 5
aipobisk_step_seconds{task="02 Тесты.md",quantile="0.95"} 610
aipobisk_nudges_total 2
aipobisk_wall_clock_seconds 2520
```

Реализация на `http.server` (stdlib), читает events.jsonl при каждом запросе —
состояние не хранится в памяти, переживает перезапуск.

**Критерий:** `curl localhost:9099/metrics` отдаёт метрики; `promtool` не ругается.

## Этап 5. Пороги и алерты

Мониторинг без порогов — просто красивые цифры.

| Условие | Порог | Что значит |
|---|---|---|
| шаг не завершён | > `step_timeout_sec` × 0.8 | агент залип |
| nudges за шаг | > 3 | модель в петле подтверждений |
| retries подряд | = `max_retries_per_step` | будем менять модель |
| доля `fatal` | > 30% за прогон | сломана конфигурация, не модели |
| p95 шага | > 2× медианы | деградация провайдера |
| задач в очереди | > числа воркеров | недобор параллелизма |

`ai_Pobisk.sh check` — печатает нарушенные пороги и выходит 1.
Для фоновых прогонов: `--notify-cmd` — шелл-команда при срабатывании
(например отправка в Telegram).

**Критерий:** искуственный прогон с залипанием даёт `check` → exit 1.

## Этап 6. Здоровье скиллов

Расширить `skills` до живой картины по `model-stats.json`:

```
skill      calls  ok%   p95     state
cline      12     75%   9.0s    healthy
nvidia     5      40%   120s    2 models cooling down
```

Плюс `ai_Pobisk.sh skills --probe` — реальный胖 ping каждой модели
(дорого, только по запросу).

**Критерий:** `skills` показывает ok% и p95 из накопленной статистики.

---

## Этап 7. Ретроспектива

`ai_Pobisk.sh report [--run ID]` — отчёт по прогону:
что заняло время, какие модели подводили, сколько стоило ротаций,
где были nudges. По events.jsonl, постфактум.

Хранить события минимум 10 прогонов (ротация уже есть), чтобы видеть тренд:
«cline деградировал за неделю».

**Критерий:** `report` по прошлому прогону печатает разбор.

## Порядок

| # | Этап | Зависит | Выход |
|---|---|---|---|
| 1 | events.jsonl + metrics.emit | — | машиночитаемые события |
| 2 | `status --live` | 1 | агрегаты по прогону |
| 3 | `watch` | 1 | наблюдение во время прогона |
| 4 | `serve` /metrics | 1 | экспорт во внешние системы |
| 5 | пороги + `check` | 2 | алерты |
| 6 | здоровье скиллов | 1 | ok% и p95 по скиллам |
| 7 | `report` | 1,2 | ретроспектива |

Этапы 1-2 — минимально полезный мониторинг. Дальше — по надобности.

---

## Риски

| Риск | Митигация |
|---|---|
| Метрики замедляют прогон | append одной строки, без fsync |
| events.jsonl растёт | ротация уже есть (`logrot.py`) |
| `serve` держит порт занятым | `--port 0` = случайный, печатает номер |
| Монитор ломает прогон | все вызовы в try/except, метрики best-effort |
| Кириллица в метках метрик | экранировать в `serve`, ключи — латиница |
