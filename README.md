# AI-Pobisk-Commander

Control and Management of AI Agents Based on the Systems-Engineering Approach of Pobisk Kuznetsov

Управление агентами ИИ по методам Побиска Кузнецова.

ai_Pobisk — консольная утилилита, при запуске смотри параметры и конфиги.
Параметры превыше конфигов.
Используя ии агент (агенты могут быть любыми — локальными или облачными), ai_Pobisk анализирует состояние и организует выполнение задач в условиях:

- модель перестала отвечать — нужно её пинать, пока не станет понятно — работает она или уже нет.
- у модели кончились лимиты — нужно переключится на другую модель
- в аккаунте агента кончились лимиты всех моделей — нужно переключиться в другой аккаунт.
- во всех аккаунтах агента кончились лимиты — передать задачу другому агенту.
- нельзя впдадать в бесконечный цикл.
- модель что-то спросила — нужно понять и решить — дать ответ или спросить хозяина.

Чтоб тебе легче было создавать силуэт ДРАКОНа создай управляющую машину состояний и из неё создавай силуэт.

## ai_Pobisk

```bash
./ai_Pobisk.sh                              # все задачи из configs/tasks/
./ai_Pobisk.sh --task "03 добавка.md"
./ai_Pobisk.sh --dry-run                    # план, ни одна модель не вызвана
./ai_Pobisk.sh list                         # найденные задачи
./ai_Pobisk.sh skills                       # агенты и доступность
./ai_Pobisk.sh self-test                    # мета-модель + адаптеры + машина + задачи
./ai_Pobisk.sh status                       # состояние и вопросы к хозяину
./ai_Pobisk.sh drakon                       # машина состояний и силуэт ДРАКОНа
./ai_Pobisk.sh mail --wait 180              # почта: дождаться письма с кодом
./ai_Pobisk.sh signup URL --yes             # ИИ заполняет форму регистрации
```

Супервизор: берёт задачу из `configs/tasks/*.md`, нанимает рабочую модель через
`.agents/skills/`, следит за ней. Модель остановилась — определяет, фатально ли,
и продолжает если нет. Модель спросила — решает, в его ли компетенции вопрос.

Две вещи про файл задачи, обе выучены на живых прогонах:

- **Всё, что выше первого заголовка `#`, остаётся в теле.** Заголовок — это
  ярлык для лога, а не граница инструкции. Раньше преамбула молча
  выбрасывалась, и задача, у которой первой строкой стоял путь к репозиторию,
  теряла этот путь: рабочий агент запускался в `ai_Pobisk` вместо целевого
  репозитория.
- **Правка задачи — это новая задача.** В `state.json` хранится хеш тела:
  изменил текст — шаг сбрасывается в 0 и задача выполняется заново. Без этого
  переписанная инструкция считалась «уже done» и прогон заканчивался за
  секунду, ничего не сделав. Если нужно принудительно переиграть всё —
  `--fresh`.

### Продолжение после падения и `--fresh`

По умолчанию прогон **возобновляется**. В `.ai_pobisk/state.json` помечается
каждый завершённый шаг; перезапуск после падения или убийства процесса
пропускает сделанное и начинает со следующего шага. На старте супервизор ещё
проверяет `status.json` на замороженное состояние `running` и удаляет
`worker_heartbeat.json`, оставленный упавшим прогоном, — чтобы внешний
наблюдатель не принял мёртвый прогон за живой (`_recover_if_crashed`).

`--fresh` **стирает** `state.json` и `journal.md` и заставляет все задачи
начать с шага 0. Используй, когда нужно переиграть всё принудительно:
после правки инструкции, если перехэшивание не помогло, или просто чтобы
прогнать заново независимо от истории.

`--fresh` **не** трогает `.ai-rotate/model-stats.json` (здоровье моделей) —
это общий на все скиллы стор, он переживает прогоны, и сбрасывать его при
каждом рестарте нельзя, иначе ротация теряет накопленную картину «кто жив».
Сбросить здоровье отдельно:
`python3 .agents/skills/_shared/model-stats.py reset <skill>`.

Стартует с настройки себе **мета-модели** (быстрая и дешёвая, отдельно от
рабочих). Если мета недоступна — деградирует на таблицу правил, не замирает.

```
задача -> адаптер скилла -> Outcome (7 исходов)
  ok/retry/rotate_model  -> продолжить
  rotate_account         -> другой аккаунт/скилл
  question               -> компетенция: ответить самому или хозяину
  fatal/loop_guard       -> стоп, доложить
```

Ключевое решение: **единый словарь исхода** (`_shared/outcome.py`). Пять скиллов
сообщали об ошибках на пяти диалектах — cline текстом баннера, opencode кодами
0/1/2, freebuff 1/4/5, nvidia/th exit 3 + HTTP. Адаптеры в `src/adapters/`
переводят всё в семь исходов; **сами скиллы не менялись**.

### Машина состояний и силуэт ДРАКОНа

Управление — не лестница `if` в супервизоре, а таблица переходов
(`src/statemachine.py`): 13 состояний, 27 переходов, 5 терминальных.
Супервизор только исполняет то, что решила машина, — вызов адаптера, счётчик,
ротация, вопрос к мете. Поэтому картинка и код не расходятся.

```
./ai_Pobisk.sh drakon                    # силуэт текстом
./ai_Pobisk.sh drakon --svg docs/machine.svg
./ai_Pobisk.sh drakon check              # машина связна, тупиков нет
```

Готовая картинка лежит в [`docs/machine.svg`](docs/machine.svg); пересобирается
той же командой, поэтому устареть не может — расхождение поймает `drakon check`.

`drakon check` доказывает три свойства: каждое состояние достижимо из
`dispatch`, у каждого нетерминального есть выход, из каждого можно дойти до
терминала. Плюс четвёртое, про саму картинку: **каждая ветвь силуэта есть в
таблице переходов** — нарисовать несуществующий путь тест не даст.

Ствол силуэта — шаг задачи, ветви справа — пути восстановления. Порядок
ветвей и есть приоритет решений: сначала инварианты (бюджеты, ключи, «нет
файловой системы», подтверждения, `loop_guard`), потом случаи, которые код
закрывает сам (подталкивание, вопросы), и только потом мета-модель.

Состояние и разбор действий — `.ai_pobisk/{state.json,journal.md}`. Убили
процесс на середине — перезапуск продолжает с того же шага.

### Мониторинг

```bash
./ai_Pobisk.sh status              # состояние задач
./ai_Pobisk.sh status --json       # то же для скриптов
./ai_Pobisk.sh status --live       # агрегаты текущего прогона
./ai_Pobisk.sh status --live --json
./ai_Pobisk.sh watch               # живой вид во время прогона
./ai_Pobisk.sh watch --json        # одна JSON-строка на тик, для jq/бота
./ai_Pobisk.sh tail --follow       # последние события, как tail -f
./ai_Pobisk.sh check               # пороги; exit 1 если что-то не так
./ai_Pobisk.sh check --notify-cmd 'curl -s ...'   # команда при срабатывании
./ai_Pobisk.sh serve               # /metrics в формате Prometheus
./ai_Pobisk.sh serve --port 0      # свободный порт, номер печатается
./ai_Pobisk.sh report              # разбор прошедшего прогона
./ai_Pobisk.sh report --run ID     # разбор конкретного прогона
./ai_Pobisk.sh skills --probe      # реально пингануть модели (тратит запросы)
```

Каждое событие пишется и в `journal.md` (человеку), и в `events.jsonl`
(машине) — из одной точки, поэтому они не расходятся. Агрегаты: длительность,
п50/р95 шага, доля ошибок, ok% по скиллам, число подталкиваний и ротаций.

Пороги в `check`: доля `fatal`, число подталкиваний, р95 против медианы,
приближение к таймауту шага. Всё на stdlib — Prometheus не нужен.

### Кто решает: модель или код

**Решатель — мета-модель.** Код описывает только инварианты:

| Инвариант (код, модель не голосует) | Почему |
|---|---|
| бюджеты и лимит итераций | иначе «повтори» навсегда |
| креденшелы и пустой кошелёк | ретраем не починится |
| «нет файловой системы» у голых API | отсутствие способности, не невезение |
| подтверждения (`Press Enter`) | за клавиатурой никого; ответ всегда «продолжай» |
| `loop_guard` | уже крутится |

Всё остальное — многообразие поведения моделей — уходит мета-модели. Она
отвечает одним из оговоренных исходов, код проверяет ответ и блюдёт бюджеты.
Если мета недоступна, работает таблица правил: деградация, не остановка.

Инварианты живут в одном месте — `statemachine.invariant()`; там же порядок
проверок. Менять поведение восстановления нужно в таблице переходов, а не в
супервизоре: супервизор только исполняет выбранное состояние.

### Контекст кода (Graft) — выключен по умолчанию

Graft раскладывает репозиторий в папку связанных markdown-карточек, и ai_Pobisk
умеет подмешивать короткую карту в промпт рабочей модели, чтобы она начинала
с ориентации, а не с разведки. Заявлено Graft: **−42% токенов, −46% вызовов
инструментов**. Цифра из их репозитория, не отсюда.

**Выключено, и вот почему — по измерениям, а не по вкусу:**

1. Задачи бьют в `igrasu.ru`: 19 ГБ, 53 505 файлов. Граф там — не префикс к
   промпту, а отдельный проект; и `graft/` там не в `.gitignore`, то есть
   мусор попал бы в чужой репозиторий.
2. `graft ask` индексирует идентификаторы и английскую прозу. Русский запрос
   («как супервизор решает сменить модель») даёт **ноль попаданий**, тот же
   вопрос по-английски — восемь с точными `file:line`. Все файлы задач здесь
   русские, значит дорогая половина интеграции гарантированно пустая.
3. Это единственная не-stdlib зависимость в проекте. «Клонировал и работает»
   важнее, чем «может быть, −42%» на репозитории, где графа нет.

```bash
./ai_Pobisk.sh graft              # статус: CLI, граф, включён ли в промптах
./ai_Pobisk.sh graft build        # построить граф (tree-sitter, без ключа)
./ai_Pobisk.sh graft ask "вопрос" # что граф знает по вопросу
```

CLI ставить не обязательно: `npx -y @nanonets/graft@0.28.1 build` работает без
глобальной установки. Включить для своего небольшого англоязычного репозитория:
`enabled = true` в секции `[graft]` файла `configs/ai_pobisk.toml`, затем
`graft build` в нём. Без CLI или без графа промпт уходит как есть — это не
ошибка, а деградация.

Пара честных деталей реализации: `has_graph()` проверяет наличие
`graft/.graph/wiring.json` или `graft/INDEX.md`, а не просто каталога с именем
`graft` (иначе статус врал «построен» при отсутствующем CLI); карта считается
один раз на задачу и кешируется — иначе два подпроцесса на каждую итерацию
ретраев; `ask` не вызывается для кириллических запросов.

## Авторегистрация: ИИ заполняет форму, почта приносит код

Задача, у которой нет API: сайт просит имя, почту, пароль, «примите условия»,
а потом присылает код. Скрипт с селекторами умирает на первом редизайне, поэтому
решение принимает модель, а не список `xpath`. Четыре модуля:

| Модуль | Что делает | Зависимости |
|---|---|---|
| `src/mailbox.py` | IMAP: найти письмо, вытащить код или ссылку | stdlib (`imaplib`, `email`) |
| `src/pageview.py` | HTML → нумерованный список контролов `[f1]…` | stdlib (`html.parser`) |
| `src/browser.py` | руки: клик, ввод, ожидание, скриншот | **Playwright** |
| `src/signup.py` | цикл: снимок → решение → действие → снимок | — |

### Почему почта читается именно так

Код подтверждения — это не «число в письме», а **число, рядом с которым стоит
слово**. Поэтому `mailbox.py` не отдаёт первое попавшееся число: он ранжирует
кандидатов по расстоянию до подсказки («код», `code`, `otp`, `подтвержд`),
штрафует годы (`2024`), цены (`1290 руб` — только если валюта приклеена к числу,
а не просто упомянута в письме) и телефоны. Если лучший кандидат не набрал
порог — возвращается `None`, а не «ну пусть будет это». Ошибка тут стоит
заблокированного аккаунта, а «письмо не пришло» — всего лишь повтора.

Ещё три свойства, которые важнее возможностей:

* **папка открывается read-only** (`select(readonly=True)` + `BODY.PEEK[]`) —
  агент не помечает вашу почту прочитанной;
* **watermark по UID.** Перед нажатием «зарегистрироваться» запоминается
  `last_uid()`, дальше ищутся только письма с бо́льшим UID. Иначе старый код из
  прошлой попытки будет принят за новый;
* **ожидание с дедлайном.** `wait_for_code` опрашивает ящик (`poll_sec`) и
  возвращает `None` по таймауту — цикл регистрации превращает это в «нужен
  человек», а не в подстановку мусора.

### Подключение ящика (handyhost, домен igrasu.ru)

Сервер уже проверен: `mail.igrasu.ru:993` отвечает Dovecot, `IMAP4rev1`,
`AUTH=PLAIN LOGIN`, есть `IDLE` (опрос можно позже заменить на push, сейчас
достаточно `poll_sec = 5`).

```bash
# 1. Пароль ящика — в общее хранилище 0600, не в репозиторий и не в TOML.
python3 .agents/skills/_shared/secrets.py set imap_gh1 'пароль-от-ящика'

# 2. Проверить, что вход и разбор писем работают.
./ai_Pobisk.sh mail --lines 5
./ai_Pobisk.sh mail --from "no-reply" --days 2 --links igrasu.ru

# 3. Дождаться свежего кода (watermark берётся на момент запуска).
./ai_Pobisk.sh mail --wait 180 --code
```

Координаты лежат в `[mail]` файла `configs/ai_pobisk.toml`
(`host/port/ssl/user/folder`), пароль — только в env `AI_POBISK_IMAP_PASSWORD`
или в хранилище под именем `password_secret = "imap_gh1"`. Если провайдер
присылает код в нестандартном виде, есть `code_regex` — одна регулярка с
группой, и она имеет приоритет над эвристикой.

### Цикл регистрации

```
снимок страницы -> решение -> одно действие -> снимок -> ...
```

Решает `signup.heuristic()` — таблица правил: первое пустое обязательное поле,
затем чекбокс согласия, затем кнопка со словом «создать/зарегистрировать».
Модель спрашивают **только когда таблица молчит** (незнакомое поле, выбор из
вариантов, «что дальше»). Поэтому обычная форма закрывается без единого вызова
API — и `--dry-run` честно показывает план, а не пустоту.

Ключевое разделение: **модель решает, куда положить значение; программа решает,
что это за значение.** В промпт уходят только плейсхолдеры — `{{email}}`,
`{{password}}`, `{{code}}`; пароль в тексте промпта не появляется никогда.
Неразрешённый плейсхолдер (`{{code}}`, когда письма ещё нет) — это остановка,
а не подстановка пустой строки.

Что агент **не** делает, а возвращает хозяину (`status: blocked`):

* капча, код из СМС, звонок, оплата — обход капчи нарушает ToS и проигрывается
  по времени, код из СМС физически недоступен;
* уверенность модели ниже `min_confidence`;
* модель назвала контрол, которого нет на странице.

Защита от зацикливания — как в супервизоре: одно и то же действие три раза или
неизменная страница четыре шага подряд дают `loop_guard`, а не бесконечный цикл.

```bash
cp configs/profile.example.toml configs/profile.toml   # кто мы (gitignored)
./ai_Pobisk.sh signup https://site.ru/register          # сухой прогон: печатает план
./ai_Pobisk.sh signup https://site.ru/register --yes    # реально кликает
./ai_Pobisk.sh signup https://site.ru/register --yes --headless --save-password
```

Создание аккаунта — внешнее и плохо отменяемое действие, поэтому нужны **два**
согласия: `allow_live = true` в конфиге **и** `--yes` в командной строке. Без них
запуск останавливается после первого запланированного шага.

Каждый шаг пишется в `.ai_pobisk/signup/<сайт>-<время>.json`: что было на
странице, что решили, чем кончилось. Успешные аккаунты — в
`.ai_pobisk/accounts.json`; пароль (при `--save-password`) — в хранилище `0600`,
никогда в репозиторий. Автономная регистрация без такого следа — это не
автоматизация, а инцидент, который никто не сможет разобрать.

Браузер — единственная не-stdlib зависимость проекта, и живёт она **внутри
репозитория**, а не в системном Python: `.venv/` для пакета, `.playwright/` для
самого Chromium. Оба каталога в `.gitignore`, оба удаляются вместе с проектом —
на чужой машине не остаётся ни глобального пакета, ни 300 МБ в кэше.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
PLAYWRIGHT_BROWSERS_PATH=$PWD/.playwright .venv/bin/python -m playwright install chromium
```

После этого `./ai_Pobisk.sh` сам берёт `.venv/bin/python` (если он есть) и сам
выставляет `PLAYWRIGHT_BROWSERS_PATH` — переменные руками больше не нужны.
Импорт ленивый: `./ai_Pobisk.sh list` работает и на машине без Playwright, а
`signup` без него печатает ровно эти три команды вместо трейсбека.

## Запуск агентов с ротацией аккаунтов и моделей

Живые агенты — в `.agents/skills/`. У каждого свой супервизор: он сам выбирает
рабочую модель, а когда лимиты кончаются — переключает модель, потом аккаунт,
потом передаёт задачу другому агенту.

| Агент | Супервизор | Что ротирует | Моделей |
|---|---|---|---|
| **Cline** | `cline/cline-rotate.sh` | аккаунты × модели | 25 |
| **OpenCode** | `opencode/opencode-rotate.sh` | аккаунты × модели | 13 |
| **FreeBuff** | `freebuff/freebuff-rotate.sh` | аккаунты × модели (по квоте) | 16 |
| **NVIDIA NIM** | `nvidia/nvidia-rotate.sh` | модели, **параллельно** | 11 |
| **Token Harbor** | `tokenharbor/tokenharbor-rotate.sh` | модели | 4 |

```bash
cd /Users/michaelpopov/Documents/GitHub/_Different/AI/AI-Pobisk-Commander

# Cline — акт-режим, автоподтверждение
```

## Общая инфраструктура

### `.agents/skills/_shared/model-stats.py` — здоровье моделей

Одно хранилище `~/.ai-rotate/model-stats.json` на все скиллы: модель, которую
один агент признал мёртвой, не_probe-ится вторым.

- **Stability Score** — `0.30·p95 + 0.30·jitter + 0.20·spike + 0.20·uptime`
  (формула из [free-coding-models](https://github.com/vava-nessa/free-coding-models),
  кэпы подняты под медленные CLI-пробы). Средняя латентность врёт: модель со
  средним 250 мс, но p95 6 с, ранжируется **ниже** стабильных 400 мс.
- **Circuit breaker** — 3 провала подряд → cooldown 900 с. `auth_error`
  (401/403/плохой ключ) паркуется навсегда: ретраем не починится.
- **Порядок ротации** — healthy (по стабильности) → untested → cooling.
- **Family failover** — мёртвый `deepseek/*` переходит на другой `deepseek/*`,
  а не на случайную модель: середина сессии сохраняет характер модели.

```bash
S=.agents/skills/_shared/model-stats.py
python3 "$S" show                 # таблица: state, stability, p95, uptime
python3 "$S" show cline           # один скилл
python3 "$S" reset cline model    # забыть модель
```

Отключить: `CLINE_NO_STATS=1`, `OC_NO_STATS=1`, `FB_NO_STATS=1`,
`QWEN_NO_STATS=1`.

### `.agents/skills/_shared/secrets.py` — ключи API

Один файл `~/.ai-rotate/secrets.json` (**chmod 600, вне репозитория**). В
репозитории ключей нет, и `check` ругается, если они там появятся.

```bash
S=.agents/skills/_shared/secrets.py
python3 "$S" set nvidia "nvapi-..."       # добавить/заменить
python3 "$S" list                          # nvap…-ddy (70 chars) — маскирует
python3 "$S" get nvidia                    # полное значение, для скриптов
python3 "$S" check                         # права + скан репо на ключи
python3 "$S" fix-perms                     # chmod 600 после случайного 644
```

С файлом слабее 600 скрипт **отказывается работать** (exit 2) — не отдаст
ключи из доступного всем файла. Сканер ищет полные ключи, не префиксы, поэтому
`AI-Pobisk-Commander` (содержит `sk-`) не даёт ложных срабатываний.

Скрипты читают ключ так, ничего не печатая:

```bash
. "$(dirname "$0")/../_shared/require-secret.sh"
require_secrets NVIDIA_API_KEY:nvidia       # exit 2 с подсказкой, если нет
```

Подробнее: [`_shared/SECRETS.md`](.agents/skills/_shared/SECRETS.md),
[`_shared/README.md`](.agents/skills/_shared/README.md).

## Что важно знать

**NVIDIA: лимит 40 RPM на каждую модель отдельно, не на ключ.** Поэтому
`parallel` — ключевой режим: 11 моделей дают 440 RPM агрегатно против 40 при
последовательном переборе.

**Каталоги врут.** NVIDIA `/v1/models` отдаёт 82 id — отвечают 11, остальные
404 «Function not found». Token Harbor: `th-orchestra` показывает нулевую цену,
но отвечает **402**; надёжный признак бесплатности — суффикс `:free`.

**Тишина — это тоже отказ.** Ротация не ждёт супервизорские 30 минут:
`cline-rotate.sh` и `opencode-rotate.sh` раз в 30 секунд смотрят, растёт ли
сессия воркера, и если две минуты ничего не меняется — снимают вызов и берут
следующую модель на том же аккаунте. Окно и шаг настраиваются:
`CLINE_STALL_WINDOW`/`OC_STALL_WINDOW` (120 с) и `*_STALL_CHECK` (30 с).

**Медленные ≠ мёртвые.** `z-ai/glm-5.3-flash` и `moonshotai/kimi-k3`
отвечают за 60-130 с. Короткий таймаут (`NVIDIA_TIMEOUT`, по умолчанию 240)
заставит принять их за сломанные.

Детали и грабли — в `SKILL.md` каждого агента.
